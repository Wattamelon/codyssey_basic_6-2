# Phase 03 - safe-mode 구현

## 역할

너는 애플리케이션 보안과 개인정보 보호를 고려하는 Python 개발자다.

## 목표

AI API로 Git diff를 전송하기 전에 민감정보를 마스킹하고 전송량을 제한하는 safe-mode를 구현한다.

## 작업

1. `SafetyResult` 모델을 정의한다.
2. 다음 유형을 탐지하는 보수적인 정규표현식 기반 마스킹을 구현한다.
   - API Key·secret·token·password 변수 값
   - Bearer token
   - 일반적인 provider Key 형태
   - 이메일 주소
3. 마스킹 횟수를 기록한다.
4. 최대 diff 줄 수 제한을 구현한다.
5. 최대 diff 문자 수 제한을 구현한다.
6. 일부가 생략되면 안전한 안내 문구를 추가한다.
7. `enabled=False`일 때 원문을 반환하되 호출 측에서 경고할 수 있게 한다.
8. 기본값은 미션 예시에 맞춰 최대 200줄, 최대 20,000자로 둔다.
9. 실제 민감정보를 테스트 파일에 넣지 말고 가짜 값만 사용한다.

## 중요한 검증 조건

- 마스킹 후 원래 비밀 문자열이 남지 않아야 한다.
- 문자 수 제한을 적용한 최종 전송 문자열이 실제 제한을 넘지 않도록 한다. 생략 안내 문구도 제한에 포함할지 명확히 설계한다.
- 제한으로 diff가 잘릴 수 있음을 프롬프트 컨텍스트에서 알 수 있어야 한다.
- safe-mode가 보안 솔루션 전체를 의미하지 않는다는 점을 문서화한다.

## 테스트

- 가짜 API Key·이메일·비밀번호·Bearer token 마스킹
- 줄 수 제한
- 문자 수 제한
- 제한 안내 문구
- safe-mode 비활성화
- 빈 diff

```bash
python -m unittest discover -s tests -v
```

실제 Key를 출력하거나 커밋하지 않았는지 확인하고 결과를 보고한다.
